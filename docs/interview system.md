TenMatch 模拟评分面试系统开发文档

一、开发目标

基于 TenMatch 现有评分系统，复用原有 UI、评分流程、评分标准及举报逻辑，独立开发「模拟评分面试」模块，用于评分人员的招募与考核。

不重新开发评分系统，仅增加面试任务管理、测试照片上传、面试人员权限、时间控制及成绩统计功能。

核心要求：模拟面试与正式评分系统数据完全隔离，互不影响。

二、功能需求

1. 面试任务管理（管理员端）

* 创建、编辑、删除及归档面试任务。
* 设置面试名称、开始时间和截止时间。
* 批量上传、删除及调整测试照片顺序。
* 添加或移除参加面试的 TenMatch 用户。
* 查看面试人员进度及成绩统计。
* 支持提前结束面试。

任务状态：未开始、进行中、已结束、已归档。

面试任务开始并产生作答记录后，不允许修改测试照片及评分规则。

2. 面试人员及权限

统一使用 TenMatch 账号登录，不新增账号体系。

* 管理员通过 TenMatch 用户 ID 添加面试人员。
* 每名面试人员仅能访问被授权的面试任务。
* 同一任务所有人员使用相同的测试照片。
* 每人的评分、举报及进度数据独立存储。
* 面试人员无法查看其他人的评分和成绩。
* 管理员可查看全部面试人员的数据。

模拟面试权限与正式评分员权限相互独立，获得面试权限不代表获得正式评分权限。

3. 模拟评分功能

直接复用正式评分系统的 UI、五项评分维度、分数范围、计算规则及交互方式。

每张照片只有两种处理方式：

A. 正常评分

* 完成原有五项评分。
* 记录每项分数、总分及平均分。
* 标记为「已评分」。

B. 举报照片

* 使用原有举报功能。
* 标记为「已举报」。
* 举报后不显示分数。
* 不保存有效评分数据。

评分与举报严格互斥，不能同时存在。

被举报的照片不参与任何分数统计，但计入已处理数量。

未提交前允许修改处理结果，切换评分或举报时清除另一种操作的有效数据；最终提交后锁定。

4. 面试时间及进度

* 开始前禁止评分。
* 开始后允许已授权人员参加面试。
* 支持自动保存评分及举报进度。
* 显示已处理数量和总照片数量。
* 完成全部照片后可提交面试。
* 截止后自动禁止修改和提交，保留已有数据。
* 提交后的成绩不可修改。

时间控制以服务端为准。

三、成绩与举报统计

1. 个人成绩详情

管理员可查看每名面试人员的独立成绩页面。

统计内容：

统计项目	内容
面试人员	昵称、TenMatch 用户 ID
面试进度	已处理数 / 照片总数
评分数量	正常评分照片数
举报数量	举报照片数
举报率	举报数 / 已处理数
五项评分	各维度平均分
累计总分	所有已评分照片的总分之和
整体平均分	已评分照片的平均分
面试状态	进行中 / 已提交 / 未完成
提交时间	最终提交时间

支持逐张查看测试照片的完整处理记录。

已评分照片展示五项分数、总分及平均分；已举报照片仅展示举报状态，不显示评分。

所有平均分仅统计正常评分照片。无有效评分时显示「—」，不按 0 分处理。

2. 面试任务汇总

管理员可查看同一任务下所有面试人员的数据：

* 面试人员列表及完成进度。
* 每人平均分、举报数量和提交状态。
* 按人员查看完整成绩。
* 按照片查看所有人员的评分和举报情况。
* 统计单张照片的平均评分、举报人数及举报率。
* 支持按完成情况、平均分及举报数量筛选、排序。

示例：

照片	人员 A	人员 B	人员 C
001	8.5分	已举报	7.8分
002	已举报	已举报	8.0分
003	7.6分	8.2分	7.9分

表格中的分数为五项评分的平均分。

四、数据结构

建议新增以下独立数据实体：

数据实体	用途
InterviewTask	面试任务、时间及状态
InterviewPhoto	测试照片及顺序
InterviewParticipant	面试人员、权限及完成状态
InterviewResult	每人每张照片的评分或举报结果

每条结果通过 taskId + userId + photoId 唯一关联。

结果状态包括：pending（未处理）、scored（已评分）、reported（已举报）。

* scored：保存五项评分及计算结果。
* reported：仅保存举报状态，评分字段为 NULL。
* pending：无有效评分或举报记录。

数据库层保证评分与举报互斥。

五、技术要求

1. 组件复用：复用现有评分 UI、输入组件、评分校验及计算逻辑，不复制维护两套评分代码。
2. 数据隔离：模拟成绩独立存储，不写入正式评分数据库业务表。
3. 业务隔离：不触发真实用户评分更新、重新评分、正式举报审核或匹配池变化。
4. 权限隔离：服务端校验任务访问权限及数据归属，禁止越权访问。
5. 时间校验：服务端统一控制面试时间、最终提交和成绩锁定。
6. 数据一致性：评分与举报状态切换采用原子更新，防止出现两种结果同时有效。
7. 响应式适配：沿用现有 UI 设计，兼容桌面端和移动端。

六、业务流程

管理员：

创建面试 → 上传照片 → 设置时间 → 添加面试人员 → 开始面试 → 查看进度 → 查看成绩及举报统计。

面试人员：

TenMatch 登录 → 进入授权面试 → 逐张评分或举报 → 自动保存 → 最终提交 → 完成面试。

七、验收标准

* 可以创建独立面试任务，上传照片并设置时间。
* 多名面试人员可使用各自 TenMatch 账号参加同一任务。
* 每人评分、举报及进度数据完全独立。
* 评分与举报互斥，举报照片不显示、不计算分数。
* 管理员能够查看每人的五项评分、总分、平均分和举报统计。
* 支持不同人员对同一张照片的结果对比。
* 截止或提交后无法修改面试结果。
* 模拟面试不影响 TenMatch 正式评分、举报及匹配业务。

开发重点：以最小改造成本抽离现有评分功能，实现独立面试任务、独立数据权限和完整统计能力。
