# TenMatch 模拟评分面试系统开发需求

## 一、开发目标

基于 TenMatch 现有评分系统，复用原有 **UI、评分流程、评分标准及举报逻辑**，独立开发「模拟评分面试」模块，用于评分人员招募与考核。

**开发原则：** 最小化改造；模拟面试与正式评分系统的数据、权限及业务流程完全隔离。

## 二、功能需求

### 2.1 面试任务管理（管理员端）

- 创建、编辑、删除及归档面试任务。
- 设置面试名称、开始时间和截止时间。
- 批量上传、删除及调整测试照片顺序。
- 通过 TenMatch 用户 ID 添加或移除面试人员。
- 查看面试人员进度、评分和举报统计。
- 支持提前结束面试。

**任务状态：** 未开始、进行中、已结束、已归档。

任务开始且已有作答记录后，锁定测试照片及评分规则，保证结果可比。

### 2.2 账号与数据权限

- 统一使用现有 TenMatch 账号登录，不新增账号体系。
- 面试人员仅可访问其获授权的任务和本人记录。
- 同一任务的所有面试人员使用同一组测试照片，但评分、举报及进度分别存储。
- 管理员可查看任务内所有面试人员的数据。
- **面试权限不等于正式评分员权限**，两者独立授权。
- 所有权限均在服务端校验，禁止越权访问。

### 2.3 模拟评分与举报

复用正式评分系统的 UI、五项评分维度、分数范围、计算规则及交互方式。

每张照片只能有一种有效处理结果：

| 处理方式 | 数据记录 | 页面展示 |
| --- | --- | --- |
| 正常评分 | 五项评分、总分、平均分 | 显示评分结果 |
| 举报照片 | 举报状态及相关记录；评分字段为 `NULL` | 显示「已举报」，不显示分数 |

**评分与举报严格互斥，不得同时存在。**

- 举报照片计入已处理数量，但不参与任何分数统计。
- 正式提交前允许更改结果；从评分切换为举报时清除有效评分，反向切换时清除举报状态。
- 最终提交后锁定结果，不允许面试人员修改。

### 2.4 面试时间与进度

- 开始前禁止评分；开始后仅允许已授权人员参与。
- 显示已处理照片数及总照片数。
- 自动保存评分或举报进度，防止刷新或断线导致数据丢失。
- 全部照片处理完成后允许最终提交，并进行提交确认。
- 截止后禁止新增、修改及提交，保留现有记录；未完成或未提交者标记相应状态。
- 时间及提交状态以服务端校验为准。

## 三、成绩与举报统计

### 3.1 面试人员独立统计

管理员可查看每名面试人员的成绩详情：

| 统计项目 | 说明 |
| --- | --- |
| 人员信息 | 昵称、TenMatch 用户 ID |
| 完成进度 | 已处理数 / 测试照片总数 |
| 评分数量 | 正常评分照片数 |
| 举报数量 | 已举报照片数 |
| 举报率 | 举报数量 / 已处理数量 × 100% |
| 五项评分 | 各评分维度的平均分 |
| 累计总分 | 所有已评分照片总分之和 |
| 整体平均分 | 所有已评分照片总分之和 / 已评分照片数量 / 5 |
| 面试状态 | 进行中、已提交、未完成或未提交 |
| 提交时间 | 最终提交时间 |

- 可逐张查看处理记录：正常评分展示五项分数、总分及平均分；举报照片仅展示「已举报」。
- 评分均值只按**已评分照片**计算；被举报及未处理照片不计入分母。
- 无有效分数时显示 `—`，不得记为 0 分。
- 已处理数 = 已评分数 + 已举报数；完成率 = 已处理数 / 测试照片总数 × 100%。

### 3.2 面试任务汇总统计

- 展示所有面试人员的完成进度、平均分、举报数及提交状态。
- 支持按人员查看详情，按完成情况、平均分、举报数筛选与排序。
- 支持按单张照片查看所有人员的评分或举报情况。
- 统计单张照片的平均评分、举报人数及举报率。

**同一照片横向对比示例：**

| 测试照片 | 面试人员 A | 面试人员 B | 面试人员 C |
| --- | --- | --- | --- |
| 照片 001 | 8.5 分 | 已举报 | 7.8 分 |
| 照片 002 | 已举报 | 已举报 | 8.0 分 |
| 照片 003 | 7.6 分 | 8.2 分 | 7.9 分 |

表格中的分数为五项评分的平均分；单张照片的平均评分仅统计实际评分人员。

## 四、数据设计

建议新增独立业务实体：

| 实体 | 主要用途 |
| --- | --- |
| `InterviewTask` | 面试任务、起止时间和状态 |
| `InterviewPhoto` | 测试照片、所属任务及顺序 |
| `InterviewParticipant` | 参与人员、授权、进度及提交状态 |
| `InterviewResult` | 每人每张照片的评分或举报结果 |

`InterviewResult` 以 `taskId + userId + photoId` 作为唯一业务组合，处理状态为：

- `pending`：未处理，无有效评分或举报。
- `scored`：已评分，存储五项分数与计算结果。
- `reported`：已举报，评分字段为 `NULL`。

评分和举报状态切换应采用原子更新，在数据库层确保互斥。

## 五、技术要求

1. **组件复用：** 共用原有评分 UI、输入组件、校验及计算逻辑，避免维护两套代码。
2. **数据隔离：** 模拟成绩单独存储，不写入正式评分业务表。
3. **业务隔离：** 不触发正式评分更新、重新评分、举报审核及匹配池变化。
4. **权限控制：** 服务端验证任务授权、用户身份及记录归属。
5. **时间控制：** 服务端验证开始、截止及提交锁定状态。
6. **数据一致性：** 评分与举报互斥；自动保存与提交不产生重复记录。
7. **终端适配：** 沿用现有设计，兼容移动端与桌面端。

## 六、业务流程

**管理员：** 创建面试 → 上传照片 → 设置时间 → 添加人员 → 开放面试 → 查看进度 → 查看统计。

**面试人员：** TenMatch 登录 → 进入授权任务 → 逐张评分或举报 → 自动保存 → 确认提交 → 完成面试。

## 七、验收标准

- [ ] 可创建面试任务、上传测试照片并设置有效时间。
- [ ] 多名人员可用 TenMatch 账号参加同一任务。
- [ ] 各人的评分、举报及进度完全独立，无法越权查看。
- [ ] 评分与举报互斥；举报照片不显示分数，也不参与分数统计。
- [ ] 管理员可查看个人五项分数、总分、平均分及举报统计。
- [ ] 可横向比较不同人员对同一照片的评分或举报结果。
- [ ] 截止或提交后禁止修改结果。
- [ ] 模拟业务不影响正式评分、举报及匹配系统。

> **开发重点：** 在最大程度复用现有评分系统的前提下，实现独立面试任务、独立人员权限及完整评分／举报统计。
